# 每日自动运营插件

业务服务在本目录，桌面入口在 `apps/desktop/src/plugins/operations/`。首次启用规则前不会执行外部动作。界面入口：**定时任务 → 运营蓝图**，或 **设置 → 插件 → 自动运营**工作台。规则保存后由现有 Cron 每分钟检查时间表；浏览器执行器独立于聊天焦点，在 Desktop 内嵌页面运行。

## 启动与配置

规则 schema 3 将 `research`（采集）与 `topics`（选题）分开；新计划默认选题时间 09:20，旧计划继承原组合任务时间。迁移保存前后规则版本，并用已认领的 research 时段阻止 topics 重放；旧选题保留并标记继承的运营主题，需确认选用或重新生成，才用于内容生产。私有 `/topics` 与 `/topics/select` 共用 Profile SQLite，选题选择带规则版本；候选选择还带批次 ID。内容生产记录实际采用的选题与依据，手动选择不触发外部动作。

每次自动选题最多使用 40 条去重来源，每条正文输入最多 4,000 字符、最多生成 12 个候选；执行记录标注使用数/可用数，不宣称覆盖全部来源。原始正文保持完整，采集每日额度不受此模型输入边界影响。候选结果、人工选择和内容版本均持久化；主题切换后不沿用上一主题的选择。

侧栏首项“运营总览”使用私有 `GET /overview` 从当前 Profile 的 SQLite 台账聚合数据；来源正文不随汇总返回，最新执行和发布记录有界。该接口复用现有认证与 Profile 中间件，不产生模型调用或外部动作。`overview.py` 负责统计口径，桌面 `overview.tsx` 负责展示，`plugin.tsx` 通过通用导航贡献调整排序；核心侧栏不导入运营业务。“运营管理”支持 `?section=rules|content|tasks|sources|topics|reports` 直达详情。

先按根 README 分别运行 Server 和 Desktop，使用相同的 `HERMES_HOME`。如需聊天查询和 CLI，在已激活的环境启用后端插件：

```bash
./.hermes/bin/hermes plugins enable operations
./.hermes/bin/hermes ops status
```

在工作台填写主题、目标、品牌、受众、风格、网站/RSS、关键词、已确认回复知识、素材与授权。进入侧栏“账号登录”，选择平台“检查／登录”，在内嵌网页登录；登录操作会先暂停自动动作。此页面按连接和 Profile 使用独立登录状态，不共享聊天预览或系统浏览器的 Cookie。工作台的“查看执行网页”用于查看后台执行过程。

选择允许的发布、评论、回复、私信与回关动作，配置额度与时间，勾选启用并取消暂停后保存。保存是对**该版本规则范围**的持续授权，自动质量检查不会标记为人工审核。修改规则撤销尚未开始的旧动作；已提交结果仍需核对。

默认时区为 Asia/Shanghai：09:00 信息采集，09:20 选题策划，09:40 内容生产，10:00 发布；评论、收到私信、条件回关分别在 11:00 / 15:00 / 19:00 检查，21:00 日报。每日默认上限分别为来源 10,000、图文 1、主动评论 5、评论回复 20、收到私信回复 10、条件回关 5；这不是平台允许额度。来源额度可配置为 0–10,000，已有计划保留已保存的额度，可在蓝图或工作台修改。上限不代表一次调试会采满，实际数量取决于检索结果、来源可访问性和去重。模型调用另有每日上限。

## 运营蓝图

“场景模板”顶部提供 8 类业务默认配置：工厂与制造企业、本地门店与商家、电商与产品商家、个人号与个人 IP、品牌与企业账号、专业服务与工作室、知识教育与培训、社群与组织运营。选择主题后可细分子类、修改定位和检索关键词，再调整任务与时间。默认使用采集、内容生产、发布、评论、收到私信回复和日报，并预选对应授权；回关单独开启。旧计划可通过“启用默认运营模块与授权”采用新配置，再检查并应用，原时间和额度保留。

业务目录由 `business_themes.py` 提供，与执行场景共用 `/blueprints`，不新增接口。规则增加可选的 `business_theme`、`business_subtype`；旧记录读取时补为空值，不改动规则版本或历史执行记录。保存时验证子类归属；已选主题状态按主题 ID 判断，不因相同模块组合把全部主题标记为已加入。已填字段默认保留，“采用此主题的内容配置”只替换主题、目标、受众、风格、关键词，不改账号、素材、知识、排期、授权或额度。咨询提示不自动写入已确认知识。

“任务与执行”保留原有任务管理，并显示运营计划与执行器状态；顶部“选择场景”进入“场景模板”。推荐场景包括行业资讯追踪、选题与草稿、小红书日更、评论维护、咨询回复、每日复盘，组合已有模块和默认时间，并提供目标与风格建议。完整流程及信息采集、选题策划、内容生产、发布、评论、私信、回关、日报九项基础蓝图继续用于自定义。晨间简报、餐单等旧内置模板不再展示；以前创建的任务仍可管理。

1. 选择场景，点击“使用场景并调整”，在右侧填写主题与目标、勾选模块。场景只补全空白的目标和风格，并加入所需模块，保留已有模块、时间与额度。新加入的发布、评论、私信模块预选授权，已有模块保留开关。模板点击本身不执行任务；首次完整流程默认勾选采集、内容生产、发布、评论、收到私信回复及日报。
2. 配置所选模块的时间、资料、动作和额度。账号默认跟随内嵌网页扫码登录，无需预填 ID。评论回复与主动评论单独授权；私信需要已确认知识，回关需要匹配条件。可先启用计划再扫码；外部动作执行前实时识别账号，未登录时提示处理，采集、生产和日报不依赖登录。
3. 查看时间线、缺失条件与相对现有规则的变化。“保存草稿”仅保留配置；“应用并启用”更新当前计划并持续授权所选动作。现有权限、时区、时间和较低额度默认保留，只有手动修改才改变。

每个 Profile 共用一套计划、当前登录账号、额度与执行台账，重复或并发应用不会创建重复 Cron。切换 Profile 丢弃未保存的表单；已保存草稿属于原 Profile。旧规则自动迁移并保留版本，原互动时间复制到评论、私信、回关三个模块；已认领的旧阶段不重放。

内容生产独立保存版本，没有图片可保留待完善草稿。发布从当天标记为候选的版本中取最新一份，重新检查来源、素材、质量、账号与额度，不临时生成另一篇。素材、内容版本、执行记录、待处理事项、日报与实时画面均可从蓝图页面进入。调度被单独暂停或删除时会显示恢复提示，重新应用蓝图可恢复；服务或插件不可用时不会退回提示词任务发布。

私有插件接口 `GET /blueprints`、`POST /blueprints/preview`、`POST /blueprints/apply` 共用规则服务；应用需携带 `version`、`request_id`、`mode`（`draft` / `enable`）及 `policy`。同一请求 ID 可重试，不可用于不同配置；旧版本提交会被拒绝，避免覆盖其他窗口保存的设置。

## 常用平台登录状态

侧栏独立的“账号登录”页面提供小红书、知乎、B 站、微信公众号后台、抖音的登录检查记录；定时任务、蓝图库和工作台不再内嵌登录面板。微信公众号指 `mp.weixin.qq.com` 管理后台，文章可访问不算后台已登录。检查只读取明确的账号导航或登录／验证标志；不能识别时返回“无法确认”。这些平台入口用于提前检查登录，不表示已新增其他平台的自动发布适配器。

- “检查／登录”复用当前连接与 Profile 的运营内嵌网页，先暂停规则并等待当前操作退出，再打开目标平台。登录完成后回工作台恢复规则。
- 当前页面就绪后每 2 秒检查变化，扫码登录等不跳转的页面变化也能更新。已确认的登录状态与最近检查分开保存：经过多久、窗口重启、离线或识别结果不明确，都继续显示“已登录”；只有明确退出或登录失效才改为“需要登录”。静态页面的重复读取不会伪造新的确认时间。
- 旧规则若明确绑定账号，可在配置中选择“改为使用当前扫码登录账号”并保存。保留绑定时，实际识别账号与规则账号不一致时，在“已登录”旁显示账号不匹配提示；验证码也单独提示，不据此认定登录过期。检测到登录或验证要求时在应用内提示；任务执行前仍使用原有账号、授权和结果核对流程。
- 状态只适用于运营执行页面，不继承系统浏览器或聊天预览的登录情况。不保存 Cookie、密码、登录令牌、页面查询参数或正文；只保存状态、可识别账号 ID、窗口标识和服务端检查时间。
- 私有接口 `GET /platforms?worker=...` 读取当前窗口及历史状态，`POST /platforms/observe` 接受当前在线窗口的观察。它们继承宿主认证和 Profile 隔离，不修改运营授权。

自动账号模式在每个外部执行阶段先通过同一 Desktop 队列识别实际网页账号，动作持久保存识别结果并再次核对，旧动作不会改投新账号。登录状态缓存不作为执行身份依据；去重按账号与目标分别记录，原规则版本和每日总额度不变。没有登录身份时不预占动作，扫码后可重新执行。

本次使用模拟 DOM 验证识别与失败行为，未访问真实账号；网站结构变化时可能需要更新识别规则。不能从“已登录”推断平台允许某动作或下一次执行一定成功。

## 操作与恢复

- 工作台“立即暂停”阻止后续外部动作；“暂停并人工接管”开放网页交互。修改完成后重新保存并恢复规则。
- 缺少来源、素材或未通过质量检查时保留草稿，允许零发布。手动编辑保存新版本，可纳入当天候选；图片第一张作为封面。内容包 ZIP 含正文、结构化版本、来源和获授权图片。
- 页面要求登录/验证、账号不匹配或 DOM 无法可靠识别时，暂停对应能力；异常处理后重新保存规则恢复。其他能力、搜集和日报继续。
- 未知结果不会自动重发。“任务与执行”填写核对证据后，可确认成功/失败/未成功；只有确认未成功才允许重试。已提交、待审核不计为发布成功。
- 指标导入 JSON：`id`（稳定导入 ID）、`day`、`name`、`value`、`definition`、`source`，可附 `observed_at` 和 `content_id`。缺失值用 `null`；同 ID 重复导入不覆盖。只有同口径可比较指标才产生排序建议，不自动改权限或额度。
- Mac、Gateway 和 Desktop 须持续运行。窗口最小化/隐藏画面时保留网页且禁用网页后台节流；休眠和退出时无法执行。超过 30 分钟窗口的发布/主动互动不集中补发；恢复后补生成缺失日报并标记延迟。
- 日报是生成时间的不可变记录快照，晚到的人工核对保留在动作台账中。可导出 Markdown。数据保存在当前 Profile 的 `plugin-data/operations/data.db` 与 `assets/`，备份时一起备份。

CLI 与工作台使用同一业务服务：

```bash
./.hermes/bin/hermes ops pause
./.hermes/bin/hermes ops resume
./.hermes/bin/hermes ops report --day 2026-10-31
./.hermes/bin/hermes ops configure --file operations-rules.json
./.hermes/bin/hermes ops tick
./.hermes/bin/hermes ops run
```

`tick` 执行当前到期且已授权的任务；不是仅预览命令。`run` 与运营调度任务的“立即执行”忽略排期，重新执行选定模块，包括当天已完成的任务。每次手动触发独立批次，同批次重试和跨天恢复去重；规则改变后须新建批次。每批次重新保存日报，保留旧快照。全局暂停、账号、素材、知识、额度及未核对动作仍会阻止相应执行，并记录原因。执行失败时 Cron 标记失败；无来源、无候选或执行器离线会记录跳过。聊天通过 `operations_status` 读取相同记录；新增工具只在新会话加载，不重建已有会话提示词。

`manual.py` 使用现有 Cron 台账识别手动触发：当前任务运行中记录、直属脚本父进程及空 `scheduled_instant` 同时匹配才进入手动路径。不新增线程或公共接口。动作按批次去重，网页目标保持原值；后续自动调度不重复已手动处理的同一目标。

## 验证边界

运行记录可展开查看完整输出、选择文字及复制全文。`COMPLETED` 表示调度脚本正常结束；实际成果以各阶段、内容版本和外部动作台账为准。未通过检查或缺图的内容标记“待完善”，本批次摘要列出已核对成功的外部动作数量，以及未加入的发布、评论、私信模块和缺失条件。采集摘要分别显示本次新增记录与当天已有的可用资料。历史输出保持原样。

“任务详情与实时进度”显示计划用途、模块时间、历史批次和各步骤的实际进展，展开后每 3 秒刷新，可复制整份详情。`progress.py` 将运营计划及采集、模型、网页执行、产物保存事件写入通用 Cron 日志；业务原始台账仍由运营插件保存。每个 Profile 的 `cron/executions.db` 增加 `task_definitions`、`task_plans`、`task_runs`、`task_steps`、`task_events`，按执行 ID 关联规则快照与完整输出。进程失败或恢复为未知时，尚在运行的步骤标记中断，待执行步骤标记本次未执行，绝不由脚本成功推断业务成功。明细随现有执行台账清理，默认保留该 Profile 最近 1000 个终态批次，页面提供任务最近 50 批次。旧版本没有的步骤和历史快照不补造。

回归测试使用模拟网页、临时 Profile/SQLite、模拟搜索/模型回执，并经真实 Cron 子进程跑通执行链路。真实账号验收必须有明确授权，分别记录实际通过、失败及待核对项；模拟通过不代表已通过全部网站兼容性验收。当前联调结果见 `docs/dev-handoff.md`。无法识别的页面会阻止动作并展示原因，不宣称已完成。

动作预留和命令入队共用事务；旧版本仅有 queued 动作、没有任何命令的孤立记录迁移为 cancelled，并保留事件。已提交或未知动作不重放。恢复核对每条动作每天最多三次、间隔至少五分钟，只读核对失败不会永久阻断对应能力。发布检查的历史范围为已核对发布的内容，素材元数据与视觉审核明确区分。Desktop 的 `execution-clock` 在隐藏窗口保持队列心跳；`browser-navigation` 等待实际加载事件，`browser-wait` 只重试读取，绝不重试提交。

左侧“待执行任务”通过定时任务贡献区的可选 `renderUpcoming({owner})` 展示运营步骤，核心不导入运营业务。私有 `/upcoming` 返回今天剩余、明天排期及活动手动批次的待执行步骤；`/upcoming/cancel` 校验规则版本及准确日期、模块、时段和批次，然后在 `runs` 写入取消记录，与执行共用唯一键和事务认领。取消不能覆盖已经开始的步骤；重复取消幂等，重启后仍生效。独立模块继续执行，新的手动批次和后续日期仍按规则运行；人工取消当天全部日报时段后，离线恢复也不补生成该日的定时日报。

图文以用户提供的授权图片为主；第一张图片为封面。自动视频、平台全量抓取、自动获取全部指标不在首版。作者和发布时间无法取得时保留未知。RSS 使用宿主的连接时 SSRF 防护，网页检索/提取复用宿主工具。
