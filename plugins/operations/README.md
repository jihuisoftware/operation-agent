# 每日自动运营插件

业务服务在本目录，桌面入口在 `apps/desktop/src/plugins/operations/`。首次启用规则前不会执行外部动作。界面入口：**首页 → 快速开始**，后续在 **任务 → 运营计划** 统一修改。规则保存后由现有 Cron 每分钟检查时间表；浏览器执行器独立于聊天焦点，在 Desktop 内嵌页面运行。

## 业务与主题归属

层级为 Profile → 业务空间 → 主题 → 计划。业务类型、业务名称和主题名称都不是数据库主键。`workspaces.py` 管理稳定 ID 与目录，`Store` 在明确的归属下打开独立主题 SQLite；目录库负责账号共享租约、消息认领、总额度、手动请求和人工历史归属。直接 SQL 写入的产物、事件、动作与命令通过 ownership 触发器写入并索引业务/主题 ID。

私有接口沿用宿主 Profile 认证，业务请求同时携带 `business_id`、`topic_id`；缺一个或两者不匹配会拒绝。仅有一个主题时可省略；存在多个主题时必须明确指定归属。`/workspaces` 管理目录，`/workspaces/summary` 汇总，`/workspaces/worker/poll` 按账号分配命令；命令回执仍提交到命令自己的主题。选择偏好不参与服务器请求归属判断。

`workspace_runtime.py` 复用现有 Cron 扫描启用主题，按阶段轮转；`scheduled_queue` 持久化每个阶段最后一次到期项，过早的排期不写历史。`workspace_broker.py` 按账号轮转领取网页命令，统一心跳、通知与接管。直接手动触发共享 Cron 会为启用主题建立请求；主题“立即执行”先保存请求，忽略排期并允许新的执行批次。同一请求在同一主题内只运行一次，停用/归档主题不会改变其他计划。全局采集与模型额度在原有 Profile 日界线上汇总，账号动作共享额度；失败或不确定动作的预留不自动退还。

开发阶段仅接受当前数据库与规则格式，不迁移旧库、不备份旧运营数据、不维护历史待归属和旧页面链接。首次建立空白业务与主题；新记录按主题正常保存。

`workspace_resources.py` 将业务授权素材、品牌与知识同步到主题提交检查所使用的本地账本。跨主题公开来源必须明确引用；内部数据和派生分析不通过该接口转为公开资料。新增业务或复制配置不会自动开启计划。

模拟验收入口：`test_operations_workspace_pipeline.py`（两个业务、四个主题及真实业务服务）、`test_operations_workspace_http.py`（私有接口边界）、`test_operations_workspaces.py`（新建、隔离、预算、账号和改名）；Desktop `workspace.test.tsx`、`worker.test.tsx` 验证切换与后台网页生命周期。模拟通过不等于真实平台验收。

## 分析续跑与报告范围

行业分析每批最多 20 项证据，校验成功后立即保存检查点。重试或重启时复用输入未变化的批次，只调用未完成或失败批次；证据、分析配置、时间范围、数据权限或分析指令变化后重新分析。报告区分本轮模型调用和复用证据数量，取消或权限变化后不保存当前调用结果。

调试与手动执行报告仅统计当前批次的步骤、产物、事件、指标和动作；普通日报汇总整日记录。模型调用次数包含失败尝试，同一调用的用量回执不重复计数。同日其他批次采集、但本次引用的来源计入历史复用；读取失败单独展示。历史日报快照不重写，修复后的口径用于新生成报告。

业务换绑账号后，登录状态只读取新绑定账号的共享证据；新账号尚无记录时显示待检查，旧账号记录仍保留在原账号下。

## 启动与配置

规则 schema 4 增加 `organize`（资料整理与归类），使用 `organization.py` 与 `organization_catalog.py` 持久化分类资料和进度；私有 `/organized-sources` 提供当前主题分类/搜索/分页。选题和生产只消费已整理且相关的可用来源，内容版本保存 organization_ids 和整理快照。按正文及来源元数据签名增量缓存，原文更新或主题变更不能复用旧整理。短文最多四篇、总输入24,000字符；长文分段保存检查点，完整覆盖后有界合并。模型漏返时保存已校验结果，仅对缺失来源单条补试一次；未知或重复来源的条目单独拒收，其余来源继续。每批记录请求 ID、返回数量、缺失 ID 与补试标志，未完成仍标记待完善；剩余模型预算优先为后续步骤预留，不增加授权额度。

`organization_formats.py`统一短文、长文分段与合并结果的格式兼容：文本/JSON字符串列表、关键词分隔串、明确的文本包装、null和布尔字符串可规范化；无法识别的可选元素单独丢弃，必填字段或来源关联不可靠则跳过该来源。格式缺失写入uncertainties和format_incomplete，不把模型解析缺失当作原文没有内容；完整性coverage仍单独表示原文/分段覆盖。`organization_format`事件保存有界诊断，不保存完整模型正文。无效JSON、空回执经`model_output.py`分类为ModelOutputError，仅整理路径可局部跳过；规则变更、权限、取消和服务异常仍按原控制处理。

`research`（采集）与 `topics`（选题）独立配置，新计划默认选题时间 09:20。私有 `/topics` 与 `/topics/select` 共用 Profile SQLite，选题选择带规则版本；候选选择还带批次 ID。内容生产记录实际采用的选题与依据，手动选择不触发外部动作。

每次自动选题最多使用 40 条已整理来源，并按输入容量选择实际使用范围，最多生成 12 个候选；执行记录标注使用数/可用数，不宣称覆盖全部来源。原始正文保持完整，采集每日额度不受此模型输入边界影响。候选结果、人工选择和内容版本均持久化；主题切换后不沿用上一主题的选择。

侧栏首项“首页”使用私有 `GET /overview` 从当前 Profile 的 SQLite 台账聚合数据；来源正文不随汇总返回，最新执行和发布记录有界。该接口复用现有认证与 Profile 中间件，不产生模型调用或外部动作。`overview.py` 负责统计口径，桌面 `overview.tsx` 负责展示，`plugin.tsx` 通过通用导航贡献调整排序；核心侧栏不导入运营业务。详情使用当前六主入口及其页签。

先按根 README 分别运行 Server 和 Desktop，使用相同的 `HERMES_HOME`。如需聊天查询和 CLI，在已激活的环境启用后端插件：

```bash
./.hermes/bin/hermes plugins enable operations
./.hermes/bin/hermes ops status
```

首页只需选择业务类型、具体主题和工作方式；其他信息在任务中的常用/详细设置补充。进入侧栏“账号登录”，选择平台“检查／登录”，在内嵌网页登录；登录操作会先接管网页，独立采集与分析继续。此页面按连接和 Profile 使用独立登录状态，不共享聊天预览或系统浏览器的 Cookie。右上角“运营画面”用于查看后台执行过程。

选择允许的发布、评论、回复、私信与回关动作，配置额度与时间，勾选启用并取消暂停后保存。保存是对**该版本规则范围**的持续授权，自动质量检查不会标记为人工审核。修改规则撤销尚未开始的旧动作；已提交结果仍需核对。

默认时区为 Asia/Shanghai：09:00 信息采集，09:10 资料整理，09:20 选题策划，09:40 内容生产，10:00 发布；评论、收到私信、条件回关分别在 11:00 / 15:00 / 19:00 检查，21:00 日报。每日默认上限分别为来源 10,000、图文 1、主动评论 5、评论回复 20、收到私信回复 10、条件回关 5；这不是平台允许额度。来源额度可配置为 0–10,000，已有计划保留已保存的额度，可在任务的统一设置中修改。上限不代表一次调试会采满，实际数量取决于检索结果、来源可访问性和去重。正常运营的模型调用受主题每日、Profile 总额与适用的单轮额度约束，失败调用也占用额度。开发调试（单项／整链路、详细／快速）不限制模型调用次数，新调用标记为额度豁免，不占正常运营预算；调用事件、Token 与可取得的费用仍照常记录。既有历史计数不回退，模型提供方自身的限制仍可能生效。快速实测保持采集抽样，但外部动作走正式生产流程，每种最多一次。

## 可配置模型预算

运营计划的常用设置提供「按调用次数」和「按 Token 用量」两种模式。新主题默认每天 200 次，
已有明确保存的额度保持不变；Token 模式的初始输入值为 1,000,000，可自行修改。
次数范围为 0～1,000，Token 范围为 0～1,000,000,000，0 停止对应范围的正常模型调用。

「全部主题共用的模型预算」单独保存当前 Profile 的共享限制，所有业务/主题共同计量。
主题与共享预算同时生效，可采用不同模式。只有一个主题且共享预算尚未单独保存时，共享预算跟随主题；显式保存共享预算后，修改单个主题不会覆盖它。
私有 `GET/PUT /model-budget` 返回配置版本和当日次数、Token、未返回/未知用量；保存采用版本校验。

`model_budget_ledger.py` 在已有主题/共享 SQLite 中保存调用预留与回执，按运行时已归一化的
输入（含缓存）和输出累计 Token，推理不重复计算，同一次生成的多次提供方尝试合并计量。
达到预算后不再发起新调用；最后一次调用可能超出预算。Token 模式将同一预算范围的正常调用
串行准入，仍在运行的调用或用量未知会阻止后续 Token 调用。预留同时记录进程身份和运行时回执边界；
进程退出后，读取预算或再次调用时自动补记完整回执。无完整回执的中断转为“用量待核对”，不继续显示等待运行；
旧版无关联信息的预留也按未知处理。可查看 Token 用量核对，必要时切换次数模式，不将未知用量视为零。
这是用量阈值，并不等同于金额限额，不会估算未知用量为零。

首次加载补录已有调用/用量事件；无法匹配完整回执的历史调用保留为未知。切换模式、修改预算、
重启或重复读取不清空当日消耗。开发调试保持豁免并记录用量，既有历史记账不回退。

## 快速实测与本次动作授权

开发调试页提供快速实测多选框，默认空选；可全选、清空或只选内部项目。按流程顺序执行勾选项，不自动加跑前置步骤。
未选前置步骤时沿用现有有效资料；仅选择发布时绑定当天当前规则下的有效草稿，缺少则跳过。已选前置步骤失败时不能用旧产物代替。
批次只有一个「执行所选项目」入口，可选择快速或详细模式，两种模式都发送 `task=pipeline`、`tasks=[...]`。快速模式选中外部动作时携带 `external_actions=execute_once`；详细模式遵守已保存的动作授权。
`devtools/operations_authorization.py` 的授权范围仅包含所选外部动作，每种最多 1 次；只选内部项目不创建外部授权。
未选业务日报仍保存不调用模型的诊断摘要，不计为额外业务步骤；暂停继续保留原选择。同一请求 ID 改变选择会被拒绝。
目录的 `selective_pipeline_available` 标识防止新版界面向旧后台发送被忽略的选择。新批次缺少 tasks 会在启动前拒绝，旧批次仅允许原请求重放已有结果，不重跑。
已移除绕过勾选的独立全链路按钮；需要执行全部项目时先全选。单行入口标为「详细执行此项 / 快速实测此项」。当前批次未勾选的行显示「本次未选择」，不混入以前批次的状态。
日常计划的 `allowed` 开关保持原值，普通任务不能借用调试授权。缺少明确标记的旧请求拒绝执行。

`debug_authorization.py` 在原子预留和 Worker 派发时核对批次、规则版本、主题/账号归属、
存活进程与租约；限定次数在同一事务中检查。结束、租约失效、暂停或换绑后不再派发待执行动作。
生产素材、内容核验、知识、回关条件、每日额度、同账号互斥和未知结果核对继续生效。
发布快照保留原计划及本次授权依据。只读核对可在批次结束后继续，已提交动作不会自动重发。

新日报和调试详情明确区分快速生产实测与历史的只读预检查；成功数只统计核对成功的实际回执。
测试使用真实业务服务/私有 HTTP/队列及模拟平台回执，不能代替真实账号验收。

## 模型输入精简与网页恢复

任务调试每一行提供“进入详细调试”，子页面使用`/operations-debug?task=<task>&run=<batch>`，保留业务/Profile归属。
`devtools/operations_task_details.py`按批次、任务及其继续尝试隔离事件和产物；日志按事件ID增量分页，完整复制按需读取全部已保存记录。模型实际尝试与重试来自同Profile的Token台账，未知回执明确显示未知。
仅新开发调试通过`model_trace.py`保存模型业务指令、输入、返回和错误，不改变模型请求与预算；凭据字段隐藏，普通运营不增加这类快照。旧记录未保存的输入不补造。
子页面提供任务检查提示、资料/选题/内容处理入口、网页截图和既有动作核对面板；新建单任务只执行当前项，继续按钮明确继续原批次未完成项。
人工调试备注按任务追加且请求幂等，不能改变业务状态或代替动作授权。旧后台缺少`task_details_available`时提示重启，避免将接口缺失误当任务故障。

存储打开通过`storage_schema.py`只读核对已有表、索引与归属；结构齐全时不重复DDL、默认记录写入或Cron计划同步。
共享素材/知识先比较已提交内容，仅有差异时取得写事务并重新核对；比较素材时按目标主题归属规范化，避免跨主题镜像因topic_id不同而反复改写。
SQLite连接的ATTACH与初始化均纳入finally关闭范围。账号额度、动作预留与命令入队仍使用原有附加数据库事务，没有改成非原子的分步写入。
私有运营接口遇到SQLITE_BUSY/SQLITE_LOCKED返回503与Retry-After；读取可稍后刷新，写入请求不自动重放，应先核对原请求结果。
`analytics.latest`先读取当前范围内的候选报告并关闭读取连接，再做配置/权限有效性检查，避免持有未结束游标时打开嵌套连接，与并发提交形成循环等待。校验异常的traceback不再保留活跃报告游标，后续错误日志能够提交。

`model_inputs.py` 只投影模型需要的字段：历史稿件保留正文及引用标识，不重复携带其中的行业分析、
整理快照和执行元数据。选题/写作选择有完整引用支持的相关结论，保留适用范围、反向证据和待核实项；
原始报告与权限版本仍完整保存。整理资料最多 40 条且受字符预算约束，明确选择的引用无法完整纳入时
要求缩小范围，不静默删掉必需引用。质检只读取稿件引用的原文，截断处有标记，不能据此声称全量核对。
每次记录 model_input 的输入字符数及覆盖数量，超大必需输入在发起模型调用前拒绝。正常/调试预算规则不变。

网页就绪失败返回结构化错误与 submitted 标记。`browser_failures.py` 只恢复可证明未提交的读取/准备
失败；已经进入 submit 阶段或结果不明的动作仍保持保护，旧命令不重放。旧版超时暂停记录结合对应
命令及网页步骤判断，恢复过程保留记录，不需要通过修改规则版本来绕开已确认的临时错误。

评论从原搜索候选卡片打开，保留平台链接上下文，填写和提交前核对目标笔记。粉丝读取同时支持
档案链接与关系按钮，已互相关注不会再次回关。私信先查找当前网页的可确认入口，不硬跳空白路由；
通知/私信缺少稳定条目或明确空态时仍报告未确认，不能把空白页面当作执行成功。

## 网页接管与内容阶段状态

`web_control.py` 统一按所属窗口的 15 秒心跳租约判断接管，清理过期或无主标记，兼容旧的主题内记录。
真正在线的接管不能被另一窗口结束；账号冲突单独提示，不冒充人工接管。心跳只能续期已有接管，
结束后的迟到心跳不能重新建立接管，连接失效后需要重新接管。全局暂停不受接管释放影响。
Desktop `use-web-takeover.ts` 保留明确接管意图、串行发送控制请求，并拒绝晚到状态覆盖新操作。

草稿已持久化就记为内容生成完成，ready/审核结果和素材条件仍独立决定能否发布。调试发布依赖
直接报告缺失条件；旧记录的任务行根据已保存产物投影正确状态，不改写历史日志或重新消耗 Token。

## 模型与来源服务失败

模型调用沿用共享运行时已有的重试和回退，不在运营插件叠加重试。恢复后仍返回 503、网关错误、
限流或网络超时时，`model_errors.py` 记录原始错误与堆栈，提供中文恢复提示。资料整理保留有效批次，
行业分析继续汇总已有检查点并暂停后续未完成批次；结果标注待完善，不冒充全部完成。
已有可用整理资料可继续供后续步骤使用，依赖确实缺失时仍跳过；后续重新运行复用完成结果。

选题模型失败时，`topic_recovery.py` 逐项核对同日、同主题、同规则下已保存的候选；仅保留来源与整理依据仍有效、分析权限未变化的部分。
有效选题另存为当前批次产物并保留原记录，状态为“待完善”，说明“选题部分可用”，内容生产可继续。
不将部分复用伪装成完整输入的缓存命中；无有效候选时仍阻止依赖步骤，发布仍需草稿通过检查及原有动作授权。

采集优先尝试尚未读取的候选，再处理之前失败的来源，避免小批量调试反复只读同一条超时页面。
失败来源保留原始原因及中文提示，仍受原有每日重试与读取额度约束；504 服务故障不会被计作成功。

## 快速开始与统一配置

业务类型沿用 `business_themes.py` 的八类，也可自定义。业务默认值只补空白，不覆盖旧计划的定位、权限、时间或额度。首次默认自动运营，回关关闭；可选择只研究分析或准备内容。详细字段保留在任务的同一编辑器中，旧蓝图草稿可显式恢复。

`GET /blueprints` 提供目录、当前规则和就绪条件；`POST /blueprints/preview` 返回阻止保存的问题、模块条件、变更及排期。缺主题、未选择功能、无效时间或过期版本阻止保存，缺账号/素材/知识不阻止。旧 `/blueprints/apply` 继续兼容 CLI。

`POST /quick-start` 接受 `version`、`request_id`、`policy`、`start`；配置、幂等回执和首轮选项在同一 SQLite 事务保存。`GET /quick-start` 返回步骤、完整/错误事件；`POST /quick-start/cancel` 取消待执行步骤。首轮使用现有 Cron 唤醒，在同一个执行租约内串行排空，最多尝试读取 20 条和 3 个检索查询，不修改长期额度。同一请求重试或未更改计划重开不会重复运行；手动“立即执行”另建批次。恢复中断时不重放已认领步骤，不自动重发不明结果。

`POST /plan/control` 使用版本校验执行暂停、恢复和手动运行；新计划首次启用记录时间边界，首轮结束后只跑未来时段。`readiness.py` 区分用户补齐条件和正常上游产出；前者恢复后只安排未来时段，后者允许本轮串行继续。全局暂停阻止新业务执行，包括日报。

`POST /worker/takeover` 按 Profile/执行器保存人工接管，取消未开始网页命令，并在后续浏览器步骤与入队前检查。结束接管不修改全局暂停；其他在线窗口持有接管时拒绝跨窗口释放，过期窗口可恢复。`GET /library/{section}` 按页面分页读取素材、内容、互动、日报和台账，不再整页加载完整工作台。业务数据模型与公开权限继续使用原有数据集服务。

## 常用平台登录状态

侧栏底部独立的“账号”页面提供小红书、知乎、B 站、微信公众号后台、抖音的登录检查记录；任务和设置不再内嵌登录面板。微信公众号指 `mp.weixin.qq.com` 管理后台，文章可访问不算后台已登录。检查只读取明确的账号导航或登录／验证标志；不能识别时返回“无法确认”。这些平台入口用于提前检查登录，不表示已新增其他平台的自动发布适配器。

- “检查／登录”先接管当前账号并等待网页操作退出，再切到该账号对应平台的独立内嵌页面。小红书、知乎、B 站、微信公众号后台、抖音在运营画面顶部切换，其他平台首次打开时才创建页面；切换或收起不会销毁已打开页面，也不会重载正在扫描的二维码。登录完成后点击“结束接管”，全局暂停状态保持不变。
- 每个已打开的平台页面就绪后每 2 秒独立检查变化，切换到后台后仍检测，扫码登录等不跳转的页面变化也能更新首页与账号页。已确认的登录状态与最近检查分开保存：经过多久、窗口重启、离线或识别结果不明确，都继续显示“已登录”；只有明确退出或登录失效才改为“需要登录”。静态页面的重复读取不会伪造新的确认时间。
- 规则若明确绑定账号，可在配置中选择“改为使用当前扫码登录账号”并保存。保留绑定时，实际识别账号与规则账号不一致时，在“已登录”旁显示账号不匹配提示；验证码也单独提示，不据此认定登录过期。检测到登录或验证要求时在应用内提示；任务执行前仍使用原有账号、授权和结果核对流程。
- 每个账号只有一条网页执行队列，小红书任务固定使用小红书页面，其他平台页面不领取任务。连接、Profile 和账号继续隔离登录数据；同一账号的各平台页面沿用原有持久分区，Cookie 按站点隔离，已有登录无需迁移。应用重启后按需重新打开页面，保留持久 Cookie。
- 状态只适用于运营执行页面，不继承系统浏览器或聊天预览的登录情况。不保存 Cookie、密码、登录令牌、页面查询参数或正文；只保存状态、可识别账号 ID、窗口标识和服务端检查时间。
- 私有接口 `GET /platforms?worker=...` 读取当前窗口及历史状态，`POST /platforms/observe` 接受当前在线窗口的观察。它们继承宿主认证和 Profile 隔离，不修改运营授权。

自动账号模式在每个外部执行阶段先通过同一 Desktop 队列识别实际网页账号，动作持久保存识别结果并再次核对，旧动作不会改投新账号。登录状态缓存不作为执行身份依据；去重按账号与目标分别记录，原规则版本和每日总额度不变。没有登录身份时不预占动作，扫码后可重新执行。

本次使用模拟 DOM 验证识别与失败行为，未访问真实账号；网站结构变化时可能需要更新识别规则。不能从“已登录”推断平台允许某动作或下一次执行一定成功。

## 操作与恢复

- 任务中的“全局暂停”阻止所有新的业务执行；运营画面“人工接管”只暂停网页。结束接管不自动恢复全局暂停。
- 缺少来源、素材或未通过质量检查时保留草稿，允许零发布。手动编辑保存新版本，可纳入当天候选；图片第一张作为封面。内容包 ZIP 含正文、结构化版本、来源和获授权图片。
- 页面要求登录/验证、账号不匹配或 DOM 无法可靠识别时，暂停对应能力；异常处理后重新保存规则恢复。其他能力、搜集和日报继续。
- 未知结果不会自动重发。“任务与执行”填写核对证据后，可确认成功/失败/未成功；只有确认未成功才允许重试。已提交、待审核不计为发布成功。
- 指标导入 JSON：`id`（稳定导入 ID）、`day`、`name`、`value`、`definition`、`source`，可附 `observed_at` 和 `content_id`。缺失值用 `null`；同 ID 重复导入不覆盖。只有同口径可比较指标才产生排序建议，不自动改权限或额度。
- Mac、Gateway 和 Desktop 须持续运行。窗口最小化/隐藏画面时保留网页且禁用网页后台节流；休眠和退出时无法执行。恢复时每个模块只补最近一次到期任务，更早时段忽略，不生成历史任务或错过执行记录。最近一次已有执行或取消记录时不回退补旧任务。日报也只补最近一份应生成的日期并标记延迟；其他业务动作使用实际执行当天的额度，历史执行记录保留。
- 日报是生成时间的不可变记录快照，晚到的人工核对保留在动作台账中。可导出 Markdown。数据保存在当前 Profile 的 `plugin-data/operations/data.db` 与 `assets/`，备份时一起备份。

### 发布核对与证据管理

“任务与执行”中的动作卡提供异常说明、下一次检查、只读“立即核对”、最终稿图文预览、逐项差异、人工核对历史和诊断包下载。最终稿在预占动作时与命令一起入库，固定账号、内容、图片顺序、来源和规则版本；后续修改资料不改变已经排队的稿件。人工结论追加保存，不覆盖自动回执；并发或迟到的自动检查不能撤销人工决定。

提交命令与核对命令的排队期限分别为 120 秒和 180 秒；执行器实际领取后，统一获得最长 10 分钟的执行期限，心跳不会续长这段期限。提交回执先入库并原子入队只读任务；提交后断线或到期只核对原结果，不重新发布。审核中按最长一小时间隔继续复查，七天后转人工；网络或不明确结果八次后转人工。重复点击“立即核对”共用已有核对命令，规则暂停或人工接管时不开始网页操作。

平台图片文件哈希不同时，可查看本地原图与平台参考缩略图、尺寸、解码像素及相似度；辅助比较不自动升级为匹配。辅助解码限制为 1600 万像素，并发限制为两张，大图或无法读取的图片仍保留未完整核对状态。

存储管理默认 30 天、自动清理关闭，可选保留期限并开启每日清理，或手动清理到期记录。只清理已处理任务的到期网页步骤和无引用截图；未处理异常、最终稿和人工结论保留。数据库空闲页可复用。诊断 ZIP 为当前动作的 JSON 日志与说明，不带图片文件或登录凭据。

CLI 与工作台使用同一业务服务：

```bash
./.hermes/bin/hermes ops pause
./.hermes/bin/hermes ops resume
./.hermes/bin/hermes ops report --day 2026-10-31
./.hermes/bin/hermes ops configure --file operations-rules.json
./.hermes/bin/hermes ops tick
./.hermes/bin/hermes ops run
```

`tick` 执行当前到期且已授权的任务；不是仅预览命令。`run` 与运营调度任务的“立即执行”忽略排期，重新执行选定模块，包括当天已完成的任务。每次手动触发独立批次，同批次重试和跨天恢复去重；规则改变后须新建批次。每批次重新保存日报，保留旧快照。全局暂停、账号、素材、知识、额度及未核对动作仍会阻止相应执行，并记录原因。执行失败时 Cron 标记失败；无来源、无候选或执行器离线会记录跳过。聊天通过 `operations_status` 读取相同记录；新增工具只在新会话加载，不重建已有会话提示词。

`manual.py` 使用现有 Cron 台账识别手动触发：当前任务运行中记录、直属脚本父进程及空 `scheduled_instant` 同时匹配才进入手动路径。不新增线程或公共接口。动作按批次去重，网页目标保持原值；后续自动调度不重复已手动处理的同一目标。

## 验证边界

运行记录可展开查看完整输出、选择文字及复制全文。`COMPLETED` 表示调度脚本正常结束；实际成果以各阶段、内容版本和外部动作台账为准。未通过检查或缺图的内容标记“待完善”，本批次摘要列出已核对成功的外部动作数量，以及未加入的发布、评论、私信模块和缺失条件。采集摘要分别显示成功、新资料、正文重复、失败、已采集跳过、未尝试及可用资料。每批统计和查询进度持久化，素材库可查看和复制；部分失败但已有可用资料时继续整理，整体保持待完善。历史输出保持原样。

“任务详情与实时进度”显示计划用途、模块时间、历史批次和各步骤的实际进展，展开后每 3 秒刷新，可复制整份详情。`progress.py` 将运营计划及采集、模型、网页执行、产物保存事件写入通用 Cron 日志；业务原始台账仍由运营插件保存。每个 Profile 的 `cron/executions.db` 增加 `task_definitions`、`task_plans`、`task_runs`、`task_steps`、`task_events`，按执行 ID 关联规则快照与完整输出。进程失败或恢复为未知时，尚在运行的步骤标记中断，待执行步骤标记本次未执行，绝不由脚本成功推断业务成功。明细随现有执行台账清理，默认保留该 Profile 最近 1000 个终态批次，页面提供任务最近 50 批次。

回归测试使用模拟网页、临时 Profile/SQLite、模拟搜索/模型回执，并经真实 Cron 子进程跑通执行链路。真实账号验收必须有明确授权，分别记录实际通过、失败及待核对项；模拟通过不代表已通过全部网站兼容性验收。当前联调结果见 `docs/dev-handoff.md`。无法识别的页面会阻止动作并展示原因，不宣称已完成。

动作预留和命令入队共用事务。已提交或未知动作不重放。恢复核对每条动作每天最多三次、间隔至少五分钟，只读核对失败不会永久阻断对应能力。发布检查的历史范围为已核对发布的内容，素材元数据与视觉审核明确区分。Desktop 的 `execution-clock` 在隐藏窗口保持队列心跳；`browser-navigation` 等待实际加载事件，`browser-wait` 只重试读取，绝不重试提交。

左侧“待执行任务”通过定时任务贡献区的可选 `renderUpcoming({owner})` 展示运营步骤，核心不导入运营业务。私有 `/upcoming` 返回每个模块最近一次待补执行、今天剩余、明天排期及活动手动批次的待执行步骤；`/upcoming/cancel` 校验规则版本及准确日期、模块、时段和批次，然后在 `runs` 写入取消记录，与执行共用唯一键和事务认领。取消不能覆盖已经开始的步骤；重复取消幂等，重启后仍生效。独立模块继续执行，新的手动批次和后续日期仍按规则运行；取消最近一次日报后不会再补更早的日报。

图文优先使用授权图片；未配图时由content_cover.py在本机生成中文文字封面，第一张图片为封面。自动生成封面不进入其他稿件的模型候选素材，也不破坏待检查草稿的输入复用。自动视频、平台全量抓取、自动获取全部指标不在首版。作者和发布时间无法取得时保留未知。RSS 使用宿主的连接时 SSRF 防护，网页检索/提取复用宿主工具。


### 采集恢复与额度

`collection.py` 负责采集；`collection_search.py` 按主题/关键词拆分查询，每次十二个，依次扩大每个查询的结果数量为 20、50、100（非平台翻页）。`collection_ledger.py` 在读取前事务预占每日额度，旧数据以当日来源数初始化；重试与失败都计入默认一万次上限，不覆盖更低配置。候选队列和查询进度按日期/主题保存，失败来源当天最多三次并原位更新，成功来源当天不重复读取。暂停或规则变化停止后续请求。

`collection_validation.py` 保留业务/签名查询参数，只去除片段和已知追踪参数；检查提取错误、空正文及短登录/验证页面，按归一正文去重（不宣称语义去重）。元数据通过现有提取工具的内部选项保留，默认模型工具输出不扩展。无效页面清除提取缓存；缺失作者、日期和图片不补造。超过一万字符的正文保留头尾片段和截断标记。搜索、来源、图片异常和每批数量均保留日志；纯来源图片不会获得发布授权。

## 草稿与质检恢复

模型生成并通过结构校验后立即保存不可发布的待检查草稿，之后才调用自动质检。质检服务失败时正文、来源和分析依据仍可查看。
当天按同一规则、选题、资料、任务、素材和分析权限再次执行内容生产，会复用最新未授权/未提交版本，继续缺失的检查或修订；已完成的有效检查与耗尽修订额度的结果不会因重复点击重跑。输入或规则变更时生成新版本。
检查完成后更新草稿的技术就绪状态并进入待审核；普通运营不因ready=true自动发布。人工审核可确认模型提示后批准完整图文，任务调试仍必须通过自动检查。

`content_evidence.py`在32,000字符正文预算内优先提供完整原文，短文剩余空间分配给长文；超长来源按稿件关键词选择原文段落并保留字符区间，区分source_truncated（抓取缺失）和excerpted（本轮节选），不把采集/统计窗口当作文章发布时间。
`content_history.py`只把实际已发布文章作为重复内容依据，不把未发布草稿或其修订版本当作已发布历史；自动文字封面带generated_typography/cover_title元数据，不要求正文声明封面引用。
`content_revision.py`依据质量检查问题最多自动修订两轮。尝试次数先持久化，模型调用不在数据库事务内；每轮另存子版本，保留parent_content_id与revision_root_id，标题变化时重绘系统文字封面，用户图片保持原引用。
修订版先保存再复检，超时后只补该版检查；规则/权限/暂停变化仍中止，已审核排期或已有发布动作的稿件不自动改写。额度不足或两轮后仍不通过时保留待审，不强制通过，也不重置正常模型预算。
通过的检查按完整请求签名复用：签名绑定检查指令、规则版本、稿件、来源正文哈希、素材和已发布历史；提交前条件不变时不重复调用模型。检查规则语义变化时同步提升content_revision.REVIEW_VERSION，以使草稿上的旧检查状态失效。

人工审核使用私有`POST /content/{id}/approve`，以稿件指纹、规则版本、排期revision做并发校验，保存账号、来源签名与UTC发布时间；`cancel-schedule`只撤销尚未建立动作的排期。
`publication_plan.py`复用每分钟运营调度与执行租约处理到期稿件，支持跨天和重启；不清空所有草稿，结果未知不重发。发布前及网页步骤开始时重查授权。
`content_runs.py`提供`POST /content/generate`完整图文生成入口；普通与快速调试中显式选择发布均有本批一次授权，其他互动权限保持原规则。人工编辑保存回原内容 ID，不新增内容列表条目；原审核与排期自动失效。修改前正文保存为 content_edit_history，已发布动作仍保留当时的内容快照。模型自动修订流程仍保留其原有版本规则。

## 完整正文与长文整理

采集使用现有提取服务的 500,000 字符上限，保存原始提取文本 `raw_text` 和清洗后的 `text`；仅移除可明确识别的登录模板与工具附加说明。仍被截断的资料不会当作完整正文。旧截断资料在下次整理时按原 URL、当前采集额度补读，修复前保留独立来源修订快照；失败或额度耗尽时保留待补读状态，不把“没读到”写成“原文不存在”。

整理请求输入最多 24,000 字符，一批最多四篇短文。长文按段落分块，已完成块与分层摘要分别保存检查点；只有全部段落完成并合并后才提供给选题和内容生产。重复执行复用已完成检查点，规则/正文发生变化时按签名重算。旧的完整短文整理继续复用，旧长文及截断资料的整理按新协议更新。

## 日报摘要与完整详情

新日报默认显示简要执行结果、主要阻塞、最多五条结论及按阶段汇总的 Token。完整分析、来源与原始回执保存在同批次独立不可变快照；日报页面通过“查看完整详情”按需读取，也可分别复制或导出摘要和详情。私有 `GET /reports/{identity}/details` 沿用当前 Profile、业务与主题作用域，列表接口只返回摘要。

暂停快照和完成快照使用不同 ID，恢复次数也纳入标识；恢复任务不会覆盖暂停时的报告。历史日报不重写，旧报告的详情接口返回其原文。

## 行业分析增量复用与选题重生

行业分析先复用验证过的固定批次，再对新增或变化证据组批，每批最多 20 条。新增资料不会重新排列已有批次。
完整来源按规范来源地址、正文与整理内容签名复用，即使次日记录 ID 改变也会映射当前引用；截断来源不跨 ID 猜测复用。
来源批次按固定文档解释，采集日期不是发布日期；业务指标和明细仍绑定统计窗口、数据版本与公开权限。
任何批次输入退出当前范围或发生变化，该批次失效；不会把包含已撤回证据的结论剪裁成新的结论。

已有批次在能重建并验证旧输入指纹时懒升级，历史记录保留。跨窗口引用旧结果会携带原始分析窗口与时间，
明确作为历史证据分析，不冒充今日趋势。无法验证的旧结果只留作历史，不计入本次覆盖。
快速实测先复用全部有效结果，最多新增分析一批；日报分别记录总量、复用、新分析与未覆盖数量。
该限制是抽样范围，开发调试的模型额度仍不限额；正常完整分析继续受已配置预算约束。

选题页提供「生成选题（优先复用）」和「重新生成选题」。同日主题、输入及权限依据一致时可复用已有候选；
显式重新生成绕过该结果缓存，并计入正常模型预算。私有 `POST /topics/generate` 接受 `version`、`request_id`、`force`，
沿用主题归属、执行租约及请求幂等；新候选不会覆盖用户已指定的题目，也不改写已有草稿。
选题结果复用不等同于整链路续跑：输入中的历史内容或资料变化仍会使缓存失效。

## 登录中断与手动继续

网页登录失效、安全验证、账号变化或执行窗口不可用会建立账号执行阻塞，并暂停当前批次；重新登录不会自动发送或解除阻塞。
独立的离线分析不受其他批次影响。调试页与任务执行历史提供继续按钮，先发只读账号探测，再恢复未完成步骤。
当天日期、规则、账号关联和引用权限必须仍有效；已提交或未知动作先核对，继续不重置动作身份、额度或快速实测一次授权。

私有 `POST /debug/{id}/resume` 与 `POST /runs/{id}/resume` 接受 `request_id`、`expected_revision`；快速实测继续携带 `external_actions=execute_once`。
请求在探测前持久化 checking，重复请求不会重复探测；进程退出可恢复 paused，历史尝试不覆盖。
`GET /runs/paused` 提供正式任务暂停记录，`/policy` 与 worker poll 的 `execution_block` 表示当前账号阻塞。
回执 `dispatch_state` 区分未开始、只读阶段和提交已开始；旧写命令缺少可靠回执时保持未知保护，不以缺少日志推断未提交。

Desktop 每条命令有取消信号和截止时间：页面加载最长 120 秒、加载结束后的单次脚本读取 10 秒、取证 3 秒，均受命令总截止时间约束。
迟到异步链不能继续提交；无法确认停止的网页实例被隔离，使用原登录分区重建。外部动作提交开始后的超时只核对，不自动重发。

## 登录观察与历史暂停

账号当前观察与批次暂停分别展示。页面恢复同账号登录后，暂停批次显示“已确认登录，等待手动继续”；
不会要求重复登录，也不会自动恢复发布或发送。旧失败原因仍在原始日志中保留。传播既有暂停不会刷新真实失效时间；
比登录观察更新的真实失败仍优先阻断。只有手动继续时的账号探测通过，才解除本次执行阻塞。
Desktop对页面加载过程中的负登录证据做同页连续确认（至少3秒）；确认期间不提交。无法确认与明确退出分开处理。

## 明确启动时核对旧登录暂停

用户明确点击启动的新调试批次或外部单项，遇到旧登录/验证暂停时，先发只读账号探测。
只有实际账号、规则、日期和账号关联一致，且期间没有新负观察、人工接管或待核对动作时，才解除旧登录阻塞并执行本次选择。
不会自动恢复其他历史批次；自动定时任务不使用这条显式启动路径。其他类型的中断与未知提交保护继续保留。
新日报记录生成时的登录观察和完整所选暂停范围，历史原因单列；原报告快照保持不变。

## 只读网页超时与步骤快照

明确点击新批次时，若旧网页超时回执能证明未开始或仅只读（submitted=false、dispatch_state=not_started/read_only、state=blocked），
可先只读核对当前窗口和账号，确认规则、账号、日期及阻塞未变化后开始新的尝试；未知提交或缺少证明的旧写命令不清除。
导航以目标文档dom-ready/页内导航/停止加载事件判定，并继续核对实际控件；不等待loadURL的全部资源结束才检查就绪。
同一URL仍加载时会等待文档就绪，导航/脚本截止时间及取消后不得继续提交的边界不变。
状态查询不改写存活执行线程的批次快照；失主恢复采用比较后更新。日报用稳定步骤slot关联已开始记录，不能仅因暂缺run_id就重复补未开始项。

调试页另有「只读检查账号与搜索页」：经真实Desktop执行器识别账号并读取搜索候选，不生成模型内容、不发布/回复、不解除既有暂停。
该诊断只使用account只读命令路径，仍检查规则、账号与人工接管；结果可用于验证网页适配，不等于外部动作已通过。
列表等待到期与网页IPC无响应分别处理：普通列表等待超时保留网页取证，不因最后一次读取预算过短而误隔离页面。

## 代理与慢网络等待

网页看得见不代表 Electron 已允许执行脚本。执行器会先等待主页面加载结束，再开始脚本执行计时；网络加载时间不计入登录/内容就绪的轮询预算。
页面加载最多 2 分钟，脚本读取最多 10 秒，账号确认 45 秒、内容就绪 90 秒；这些都是上限，正常页面立即继续。
外层组合步骤只受整条命令的硬截止约束，不再额外套一个 5 秒超时。提交前在加载后重新检查规则和接管状态，取消后不得继续派发脚本；未知提交仍只核对不重发。
后台等待遵循命令被领取后的实际 expires，不再固定在 125 秒提前中断。发布后的独立核对也使用相同加载/脚本分离逻辑。


### 独立任务的账号阻塞检查

历史网页中断、超时或登录验证失败不直接恢复旧批次。新的定时发布及手动外部任务会先通过现有只读账号探测，确认当前账号、规则、日期与执行窗口仍有效，再解除可恢复的账号阻塞；旧批次保持暂停。当前批次自己的暂停、账号切换、人工接管与相同内容结果未知的防重检查仍有效。其他独立分析任务不继承账号级网页暂停。
