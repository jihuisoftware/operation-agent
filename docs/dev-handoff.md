## 本轮已实现

- `plugins/operations/store.py`：动作与命令同事务入队，能力阻断在预留前检查；enqueue 获取既有命令，避免孤立 queued 动作。`migration.py` 只取消无任何命令的旧 queued 孤立记录，未知或已提交动作不重放。
- `outcomes.py`：未核对提交不再显示成功。`recovery.py`：每条动作每天最多三次只读核对、间隔五分钟；核对失败不永久阻断发布能力。
- `content.py` / `workflow.py`：发布重复检查使用已核对发布历史，不把修订中的旧草稿当发布历史；提供素材元数据并明确未做视觉审核。
- `report.py`：日报保留当日内容引用的历史来源链接，区分当日采集与既有资料，未核对动作不计成功。
- Desktop `execution-clock`：独立 Worker 维持队列心跳与读取等待。真实 hidden 窗口旧心跳间隔超过一分钟，新时钟连续约两秒触发，服务端在线恢复；未证明整机休眠中可以执行。
- `browser-navigation`：等待实际 did-stop-loading，不能把 loadURL 的 IPC 返回当页面完成。`page-ready` / `browser-wait`：读取就绪状态，空 document.body 继续等待；只读轮询不重试提交。
- `page.ts` / `browser.ts`：过滤屏幕外测量节点及 aria-hidden 控件，保留脚本实际错误；富文本按段落填写，正文核对归一化布局空白；点击前增加内容校验。空关键词回退运营主题。
