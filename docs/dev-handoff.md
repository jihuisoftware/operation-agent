## 实现

- `model_inputs.py` 投影历史正文、当前相关分析与整理依据，去掉模型输入中的重复分析快照、
  无关配置和非引用原文；保留完整存储/权限检查。相关结论保留反证、范围和未知项，按字符预算选入。
  必需引用无法完整纳入时明确拒绝，不静默丢掉选题引用。model_input 事件记录字符数与覆盖数量。
- 使用 11-03 资料的隔离 SQLite 快照测量，选题/写作/质检输入合计约 150 万字符降至 7.8 万，
  约减少 94.8%；这是离线请求字符量，不是实际计费 Token。没有为测量调用模型。
- `browser_failures.py` 结合回执与网页步骤，只恢复可证明发生在提交前的就绪失败。
  有 submit 开始证据或结果不明时保持保护，旧命令不重放；恢复记录保留，后续真正的阻断可重新生效。
- `interaction-dom.ts` 共用就绪/候选识别，支持粉丝档案链接和关系按钮；不凭单个“回关”按钮
  推断对方关注，也不把空白通知页当作空列表。评论经原候选卡片打开，保留签名链接并核对目标笔记。
- `browser-inventory.ts` 使用页面可确认的消息入口，不再硬跳 /im；结构化 PAGE_NOT_READY 等错误
  携带 submitted 状态。控制暂停与加载失败在确认未提交时可发起新请求。
- 通过已有失败截图确认：评论曾到 /404；粉丝弹窗已有互相关注条目；通知/私信页面没有可确认内容。
  Computer Use 的 Electron 读取仍超时，因此未完成当前真实页面验收，没有实际发布/评论/私信/回关。
