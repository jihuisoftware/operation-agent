# 问题报告：运营网页组件报错，导致已排期内容到期未发布

- 优先级：P1
- 主要负责：桌面前端；排期等待原因展示需要后台配合
- 排查时间：2026 年 11 月 10 日
- 报告日期：2026 年 11 月 11 日
- 排查版本：`803def08b3`
- 状态：代码已修复并通过隔离回归（2026-11-11）；生产实例尚未重启验收。以下运行数据为原排查快照

## 问题现象

用户已审核内容并设置发布时间，到期后没有发布，页面仍显示“已排期”，也没有明确提示网页执行器离线。

定时调度正常运行，普通内容页面仍可操作，因此用户难以发现异常。

开发 Profile 的 `logs/desktop.log` 在当天 **10:43、10:51、13:20、13:22** 均记录了该异常：

```text
Uncaught ReferenceError: back is not defined
```

## 根因定位

文件：[browser-toolbar.tsx](../apps/desktop/src/plugins/operations/browser-toolbar.tsx)。排查版本中，参数解构位于第 17 行，按钮引用位于第 33 行。

组件的 `Props` 已声明：

```tsx
back: () => void
```

但组件参数解构遗漏了 `back`：

```tsx
export function BrowserToolbar({
  status, loading, error, takeOver, login,
  hide, reopen, release, retryCheck,
  platformName = '小红书'
}: Props) {
```

随后按钮直接引用未定义变量：

```tsx
<Button onClick={back} size="sm" variant="outline">
  返回上一页
</Button>
```

**异常发生在组件渲染时，不需要用户点击按钮。** 运营网页组件无法正常挂载或持续运行，执行器心跳随之中断。

后台通过 [store_reads.py](../plugins/operations/store_reads.py) 的 `online()` 判断最近 15 秒内是否收到执行器心跳。[publication_plan.py](../plugins/operations/publication_plan.py) 的 `publish_due()` 检测到离线后直接返回，未创建发布任务，也未更新排期的阻塞说明。

```text
BrowserToolbar 渲染报错
    → 网页执行器无法正常运行
    → 后台判断执行器离线
    → 跳过到期发布
    → 页面仍显示“已排期”
```

相关前端入口：[worker.tsx](../apps/desktop/src/plugins/operations/worker.tsx)。该组件负责挂载运营画面及轮询网页任务。

## 前端修改要求

1. **修复参数遗漏。** 在 `BrowserToolbar` 参数解构中加入 `back`，核对所有调用方均传入正确回调。
2. **增加组件回归测试。** 验证组件能够正常渲染，“返回上一页”按钮点击后调用传入的回调。
3. **验证执行器生命周期。** 确认切换页面、收起运营画面后，执行器仍正常发送心跳；发生组件异常时，应显示明确错误及恢复入口。
4. **完善排期提示，与后台联调。** 到期但执行器离线时，显示“发布时间已到，正在等待桌面网页执行器连接”，并可展示最后连接时间。不能只显示“已排期”，让用户误以为任务正在正常等待。

## 后台配合项

`publication_plan.publish_due()` 当前遇到执行器离线会直接返回，建议提供结构化等待原因供前端展示，同时保留排期，不误记为发布成功。

排查时另有一条 **2026-11-09 14:09 遗留的 `BROWSER_UNAVAILABLE` 账号阻塞记录**，提示网页执行窗口中断、尚未提交。它不是本次未创建发布任务的直接原因，但恢复执行器后仍需核对。

前端修复后，应通过现有账号检查和恢复流程处理，不能自动清除所有阻塞或重发结果未知的历史动作。

## 验收标准

- 启动桌面、打开或收起运营画面，不再出现 `back is not defined`。
- “返回上一页”“返回首页”功能正常。
- 执行器心跳持续更新，后台在线判定正常。
- 使用隔离数据和模拟执行器，确认到期稿件只创建一次发布任务。
- 执行器离线时，页面明确显示等待原因；恢复后不重复提交。
- Desktop 类型检查和相关组件、执行器测试通过。
